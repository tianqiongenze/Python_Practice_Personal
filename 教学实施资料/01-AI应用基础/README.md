## 一、目录结构与用途

```
01-AI应用基础/
├── README.md                 ← 本文件（组织管理说明）
├── requirements.txt          ← 依赖清单（含CPU版PyTorch说明）
├── 环境搭建指南.md            ← 开课前一周机房部署清单
├── 数据与工具/
│   ├── generate_data.py      ← 一键生成全部本地数据（M1泵数据/M2轴承序列+焊接图像/M3缺陷图像/M4语料与知识库）
│   └── mock_llm_server.py    ← 本地模拟LLM服务（OpenAI兼容接口，离线可用，M4.2课内必做环境）
├── 工单任务书/                ← 每周一份，课前发放（含资讯导学单+及格/优秀标准+D/C/B/A量表）
├── 学生代码框架/              ← 每周一个starter（TODO引导），随工单发放
└── 教师参考/
    └── solutions.py          ← 8个工单的可运行参考实现（教师专用，勿下发学生）
```

## 三、使用流程（六步法落地）

1. **课前（资讯·计划）**：在课程平台发布当周工单任务书+starter；学生完成导学单预习自测，提交初步计划。
2. **课中**：决策10min（工单内含决策矩阵页）→第一轮实施30min→三层检查复盘5min→第二轮实施25min→总结评价10min（共80分钟，每课时40分钟）。
3. **课后24h内**：按工单内D/C/B/A量表评分并反馈；困难学生推送补强任务。
4. **每4周**：ABCD角色轮换（用04-教学管理工具包的轮换表）。

## 四、可行性红线（v2.0核心变更，务必遵守）

- 全部课内任务**CPU可完成、离线可运行**；不得依赖外网下载（权重/数据一律课前从资料包导入）。
- M3.2 以"预训练模型CPU推理+阈值优化"为课内主线；微调训练仅教师演示（GPU或课后云端选做）。
- M4.2 课内一律使用 `mock_llm_server.py`（OpenAI兼容本地服务）；真实大模型API仅课后选做且须先过数据脱敏合规检查。
- 报告与提交物统一UTF-8编码，文件命名：`学号_姓名_M1.1.zip`。
